**Step through roof planes with the bracket keys**

Reviewers checking a large design have to hunt for each roof plane with the mouse. Design review wants a keyboard step-through: `]` selects the next roof plane and `[` selects the previous one, wrapping at both ends, so a reviewer can walk the whole roof without leaving the keyboard.

Add `packages/frontend/src/features/3d-viz-v2/api/logic/step-roof-plane-selection.ts` exporting `stepRoofPlaneSelection(planeIds, selectedId, direction)`, which returns the id the step lands on: the neighbour in `direction` when `selectedId` is in the list, the first id when nothing is selected, wrapping at both ends, and `null` when the list is empty. Add `packages/frontend/src/features/3d-viz-v2/api/hooks/use-roof-plane-step-3d.ts` exporting `useRoofPlaneStep3D({ planeIds, selectedId, onSelect, disabled })`, which watches for those two key presses and calls `onSelect` with the result.

The shortcut has to work while the reviewer's focus is anywhere in the editor, not only on the canvas, so it listens at the page level rather than on one element. Ignore the press while a text field or a `contenteditable` element has focus, and only act when the 3D editor owns the keyboard — `owns3DKeyboard` in `api/logic/keyboard-ownership.ts` is the same live check the sibling plane shortcuts make. Unit tests for the pure step function go in `api/logic/__tests__/`, following the conventions of the neighbouring tests there. Wiring the hook into the editor tree is a separate follow-up ticket; keep this change to the two modules and the tests.
