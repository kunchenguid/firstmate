# Command Code worker verification

Audience: maintainer verification.

Verified 2026-10-05 on Linux x86_64 (`Linux 7.2.5-3-omarchy`) with Command Code `1.74.1` from the AUR `command-code` package, Node `v26.8.1`, tmux `3.7c`, and Herdr `0.9.3`.
The [adapter reference](../../.agents/skills/harness-adapters/references/harness/commandcode.md) owns operating facts; executable owners carry launch and state mechanics.
This verification covers crewmates and scouts on model `deepseek/deepseek-v4.1-flash`, with tmux as the guarded runtime backend and a named Herdr lab session for the same lifecycle on Herdr.
Primary, secondmate, quota-provider, and typed-dispatch integration are outside this guarantee.

## Refresh commands

```sh
commandcode --version
commandcode --help
commandcode status
commandcode --list-models
bin/fm-test-run.sh tests/fm-commandcode-harness.test.sh tests/fm-tmux-agent-liveness.test.sh
FM_COMMANDCODE_SIGNALS_LIVE=1 bin/fm-test-run.sh tests/fm-commandcode-signals-live-e2e.test.sh
```

The credentialed guard copies `~/.commandcode/auth.json` into an isolated home, uses a private tmux socket, and runs the actual command generated by `fm-spawn.sh`.
That home carries a user `SessionStart` hook that must keep running beside the per-process busy mod, and the worker's own commit must carry no Command Code attribution.
Worktree allocation and initial endpoint delivery use the portable fixture; steering, interrupt, exit, and relaunch then use the real backend, the real vendor process, and the real control plane.
It skips when signed out or when no file credentials can be isolated; the shared live gate owns absent-tool and opt-in behavior.
Failures name the installed Command Code version.

## Observed vendor surfaces

`/usr/bin/commandcode`, `cmd`, `cmdc`, and `command-code` are wrappers that exec `/usr/lib/node_modules/command-code/dist/index.mjs`; the running process sets its title, so `ps -o comm=` reports `command-code` and the rewritten argv is the same word.
`commandcode status` reported `Authenticated as <account>` with provider `Command Code`, and `commandcode --list-models` listed `deepseek/deepseek-v4.1-flash` and `deepseek/deepseek-v4.1-flash-fast` among 85 models.
Both DeepSeek V4.1 Flash models answered `--effort bogus` with `Unknown effort "bogus". Supported: off, low, high, max.` and exit status 1; `medium` and `xhigh` were refused the same way, while `low` and `max` printed `Reasoning effort set to ... for DeepSeek V4.1 Flash.`
An unknown model exits with `Error: unknown model "deepseek/no-such-model".`
`--yolo --trust --skip-onboarding` started in a fresh repository with no trust or permission prompt, and the footer read `» permission bypass on`.
A message after `--` started the first turn; a message beside `--resume <id>` was ignored and the resumed session waited at an empty composer.

`--config theme=light` under a scratch `HOME` wrote `{"theme": "light"}` into `~/.commandcode/config.json`, and `--config attribution.commit=` exited with `Unknown config setting: attribution.commit`, so `--config` is not a per-process mechanism.
Hook settings offer `PreToolUse`, `PostToolUse`, `Stop`, and `SessionStart` only.
A mod passed with `--mod` and `--mod-option` loaded for that process only and logged, for one turn, `run_start`, then `onRunEnd end_turn` and `run_end "end_turn"`; an Escape interrupt logged `interrupted` and `run_end "interrupted"`; `/quit` logged `onSessionEnd shutdown` and `session_shutdown`; `--resume` logged `onSessionStart resume`.
The user `SessionStart` hook fired beside the mod, and the user `settings.json` was byte-identical after the run.
On every start the CLI creates an empty `.commandcode/taste/taste.md` in the project for taste learning, whose only switches are settings files.

The idle composer row is `❯` in the default foreground, the reverse-video cell `A`, then `sk your question...` in `38;2;138;148;168`, between two rules in the same colour; typed text is the default foreground with a reverse-video cursor cell after it.
With `COLORTERM` unset the placeholder became `38;5;145`, and with `NO_COLOR=1` the cursor cell lost its reverse video while the truecolor stayed.
The terminal cursor sits on a blank row below the footer.
A running turn renders one status row such as ` ○ Contemplificating…  esc to interrupt • 2s • ↓ 41`, later ` ⌘ Choreographing…  esc to interrupt • 1m 30s • ↓ 1.4k`, with escape sequences between `esc` and `to interrupt` in the styled capture.
One Escape on a running turn printed `❯ Interrupted · What should Command Code do instead?` and left an empty composer.
On an idle agent, two Escapes 0.1 or 0.3 seconds apart opened the `Rewind` picker (`Select a checkpoint to restore your session`, footer `Press Enter to select · Esc to cancel`), gaps of 0.6 seconds or more did not, two presses sent back to back parsed as one key and opened nothing, and one Escape closed the picker.
`/quit` returned to the shell and printed `Resume this session with:` followed by `cmd --resume <session-id>`.
The slash popup listed `/no-mistakes` as `[skill]` from `~/.agents/skills`.
A worker commit composed by the model carried `Co-authored-by: CommandCodeBot <noreply@commandcode.ai>`, which the fleet commit-msg strip now removes.

A real `fm-spawn.sh` Command Code launch, run in a pane of a named Herdr 0.9.3 lab session provisioned through `bin/fm-herdr-lab.sh` with the task record pointing at that pane, and with the captain's real user `settings.json` (Herdr's own Command Code `SessionStart` hook) copied into the isolated home, produced:

Herdr names the pane `cmd` from its own detection, which is the identity the shared composer classifier accepts beside the tmux probe's `commandcode`.
The lab teardown's fleet-state tripwire passed and the `default` session was unchanged.

## Coverage and limits

The portable regression drives ancestry evidence, rejects an unrelated process name, checks the single-press interrupt and rewind-picker tables, reads a captured composer screen with and without a Command Code identity (asserting the divergence), keeps typed text pending, checks both delivery signals independently, drives the busy mod's lifecycle with stale-generation and unconfigured-option rejection, and verifies worker-only launch, the per-process mod options, verified-only effort, and taste-state exclusion.
`tests/fm-tmux-agent-liveness.test.sh` proves with real tmux processes that a `command-code` foreground reads alive and a blind cursor row still yields `empty` or `pending`, gated on that process identity.
The live guard checks the launch brief, model, effort, identity, busy mod, user-hook coexistence, settings immutability, commit attribution, doorbell acknowledgement, idle and busy interruption, the rewind picker, exit, native resume, and relaunch.
Zellij, Orca, and cmux were inspected through their existing backend-neutral delivery and key surfaces, not live-tested here; their composer reads carry no Command Code identity, so a steer there is not proven deliverable.
Orca's existing lack of Escape delivery means a Command Code interrupt is refused there.
macOS process naming was not observed.
