# Merged-PR teardown actuator

`bin/fm-merged-teardown.check.sh` is the deterministic lifecycle hook that replaces prompt-memory driving of worker teardown after a merge.
A registered `state/merged-teardown.check.sh` wakes the watcher on its normal `*.check.sh` sweep, reads each ship task's latest durable status line, and drives `bin/fm-teardown.sh` once the task's PR has merged.

## Trigger and authority

A task's `state/<id>.meta` must record `kind=ship`, and its latest `state/<id>.status` line must be either:

- `done [at=<epoch>]: PR https://github.com/.../pull/<n>` (the task ended by reporting its PR), or
- `paused [at=<epoch>]: ... awaiting captain merge of https://github.com/.../pull/<n>` (the task is waiting on the captain merge it named).

No other status line counts.
A ship task that stopped for another reason - a blocker, a draft decision, a local-only landing - keeps its own lifecycle and is never dispatched from here.

The check resolves the URL once per sweep with `gh pr view <url> --json state --jq .state`:

- `MERGED` runs `FM_HOME=<this-home> bin/fm-teardown.sh <id>` from the same repo the check ships in.
- `CLOSED` reports `closed-no-merge: <id>` once and drops the id; the captain decides what to do with a rimmed PR, never this check.
- `OPEN` (or any other state, including a transient gh failure) does nothing until the PR settles, then starts a clean count.

The first non-zero teardown exit (unlanded-work refusal, etc.) reports `teardown-refused: <id>: <first stderr line>` once and stops tracking the id.
The captain's durable record names the surviving endpoint; the watcher's stale path remains the single stale monitor.

## One-shot bookkeeping

`state/.merged-teardown-acks/` owns the no-repeat guarantee with three single-link files:

- `<id>.done` - teardown succeeded; never invoke it again for this id.
- `<id>.closed-no-merge` - the CLOSED wake was printed; do not wake again.
- `<id>.teardown-refused` - the refusal wake was printed; do not wake again.

Files are written only by this check, in its own directory, with `umask` inherited from the watcher.
They are one-shot latches, not state machines: delete a latch only when rerunning that event would be correct.

## Wiring

`arm` writes the byte-static shim below and binds it with `bin/fm-check-register.sh merged-teardown` (mode 0700, sha256-bound in `state/merged-teardown.check-trust`); the watcher then runs it on the same cadence as every other `state/*.check.sh`:

```bash
#!/usr/bin/env bash
# Auto-generated by fm-merged-teardown.check.sh - merged-teardown shim.
# The watcher validates these bytes, then dispatches the trusted check script.
export FM_HOME=<resolved-home>
exec <repo>/bin/fm-merged-teardown.check.sh check
```

`disarm` removes the shim and its trust binding; the ack directory stays behind so a later re-arm does not repeat past events.
Only `bin/fm-merged-teardown.check.sh` and the ack dir are written; it is read-only against `projects/` and every other record under `state/`, and it never touches the no-mistakes daemon.

## Proving a run before arming

`dry-run` (or `FM_MERGED_TEARDOWN_DRY_RUN=1 check`) walks the same sweep with teardown and ack stamping disabled.
A fleet whose ship tasks are all already resolved prints exactly `dry-run no-op`; an eligible task reports the dispatch it would have performed under `merged-teardown(dry): <id> would be torn down after PR merge`.
Dry-run refuses, never silently normalizes, when the seam points at the real `bin/fm-teardown.sh` rather than a fixture stub.

Behavior proofs live in [`tests/fm-merged-teardown.test.sh`](../tests/fm-merged-teardown.test.sh).
