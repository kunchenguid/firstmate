Mode: OpenCode TUI plugin background wake.

When this session owns supervision and away mode is not active:
1. At the start of EVERY wake-handling turn - including a turn that also answers a user Q&A or Lavish diagram question - run `bin/fm-wake-drain.sh` BEFORE any peek, read beyond the reason line, steer, or new work. Session start is the only exception because its one-shot digest already presented the queue while locked or deliberately left it untouched in read-only mode (AGENTS.md §8). The drain presents the durable wake queue as this turn's work queue and always prints `WAKE_ACK_REQUIRED`; after handling all emitted wakes and reconciling its `OPEN DECISIONS` / `UNREAD STATUS` / `RECORD DIVERGENCE` sections, run the exact generation-bound `--ack-through` command printed by the drain. Until that ack, interruption leaves the work durable for idempotent re-handling. Then translate each durable result (e.g. `done: PR https://...`) into a captain-facing message per AGENTS.md §9: full `https://` PR URL, concise outcome summary, and risk level for `direct-PR`; never relay raw `done:` / `signal:` / `watcher:` terms verbatim. After that translation, provide the required follow-up: for a terminal done/merged/failure/blocked, either state the required captain action (review URL, decision, blocker) or advance to the next queued plan step (check `tasks-axi ready` / `data/backlog.md` and name the project + mode); do not stop after translation without a follow-up or next-step statement. The drain's `.hb-surfaced-*` bookkeeping prevents duplicate re-surface of the same `done:`.
2. First cycle: let `.opencode/plugins/fm-primary-watch-arm.js` arm supervision after the OpenCode session goes idle.
3. The plugin listens for `session.idle`, spawns `bin/fm-watch-arm.sh --restart` without awaiting it in the idle handler, and owns every later successor launch. It verifies `state/.watch.lock` holds a live identity-matched watcher with a fresh beacon (`state/.last-watcher-beat` within `FM_GUARD_GRACE`); `bin/fm-watch-arm.sh` prints `watcher: started` or `watcher: attached (beacon fresh)` on success and a typed `watcher: FAILED` on failure.
4. After an actionable child close (`signal:` / `stale:` / `check:` / `heartbeat`), the plugin rechecks session-lock ownership and verifies one singleton successor before it calls `client.session.promptAsync` with a `watcher`-kind operational input; its bounded fallback (exponential retry up to `FM_WATCH_REARM_RETRY_LIMIT`, then typed restoration failure) is defined in `docs/watcher-continuity.md`. The prompt is the wake-handling turn's entry point - treat that next turn as a wake-handling turn and obey step 1 before any other work, even if the prior turn was a user Q&A. The watcher replaces its terminal sleep with a bounded native event wait (`pane.agent_status_changed` on `herdr` with `config/backend herdr` / `HERDR_ENV=1`), so `blocked` surfaces sub-second; the poll loop (`FM_POLL 15`, `SIGNAL_GRACE 30`, `FM_CHECK_INTERVAL 300`, `HEARTBEAT 600→7200`, `STALE_ESCALATE 240`, `BUSY_TURN_MAX 3600`) remains the fail-closed backstop.
5. Ordinary wake: do not ask the model to re-arm because continuity is plugin-owned. Keep exactly one live cycle - do not spawn a second watcher when a healthy one already exists. Never `pkill -f bin/fm-watch.sh`; that pattern kills sibling homes. While `state/.afk` exists, the daemon owns triage and the watcher reverts to daemon-managed one-shot mode.
6. An unexpected child close enters bounded exponential retry (`FM_WATCH_REARM_RETRY_BASE_MS` → `FM_WATCH_REARM_RETRY_MAX_MS`), and an exhausted retry or lost session lock is surfaced as a watcher failure instead of disappearing.
7. Failure or missing cycle only: if the plugin reports a watcher failure (`watcher: FAILED` with broadcasted `state/.watcher-down` generation), drain queued wakes, inspect the failure text, and use `bin/fm-watch-arm.sh` manually only as a short recovery probe. The drain's generation-bound `WAKE_ACK_REQUIRED` retires that `down` episode only after the queue is empty; a `generation` mismatch is non-fatal - re-drain and ack the newer generation.
8. Never use shell `&` for watcher supervision.
   The arm mechanism above is plugin-owned, not a model tool call, but a manual recovery probe that backgrounds, pipes, or bundles the arm is denied automatically by the PreToolUse seatbelt (`.opencode/plugins/fm-primary-pretool-check.js`, `bin/fm-arm-pretool-check.sh`).
9. Do not rely on this plugin in headless `opencode run`; firstmate primary supervision targets persistent OpenCode TUI sessions. Validate with a no-op scout that `done:` surfaces in chat within one watcher cycle (≤ `FM_POLL` 15 s + `SIGNAL_GRACE` 30 s) without the captain having to ask, and that `state/.hb-surfaced-*` prevents duplicate re-surface.

OpenCode's persistent TUI plugin runtime is the wake mechanism.
The plugin applies in the main primary checkout and a secondmate's own home, and stays silent only in child crewmate and scout worktrees.
