# Lists and headings

Lookup owner: [Lists](https://developers.google.com/style/lists) and [Headings and titles](https://developers.google.com/style/headings).

## Heading hierarchy

- One level-1 heading per page for the title or main topic.
- Increase heading level by one step at a time (`h2` after `h1`, and so on).
- Do not choose a heading level for visual size alone.
- Keep headings unique and descriptive for navigation and screen readers.

## Introducing lists

- Precede most lists with a complete introductory sentence.
- End the introduction with a colon when the list immediately follows.
- Do not let list items finish a sentence fragment started in the introduction.

Recommended pattern:

```md
To configure the client, follow these steps:

1. Install the SDK.
2. Set your API key.
3. Run the verifier.
```

## List type selection

| Need | List type |
| --- | --- |
| Ordered steps or priority | Numbered |
| Unordered options or examples | Bulleted |
| Term plus definition | Description list |
| Compact run-in term plus gloss | Description list with run-in headings |

Do not use a list for a single item.

## Parallelism and punctuation

- Start each item in the same grammatical pattern when possible.
- Capitalize the first word of each item unless case carries meaning (for example glossary entries).
- End items with periods when they are sentences or contain verbs.
- Omit end punctuation for single-word items, items without verbs, all-code items, or link-only items.
- When items mix formats, rewrite for parallel structure or punctuate every item consistently.

## Serial commas

Use the serial comma in inline lists and before the final conjunction.

Recommended: `event logs, clickstream data, and transactions`

Avoid trailing `etc.` when the introduction already signals the list is illustrative.

## Sentence case recap

Capitalize only the first word and proper nouns in headings, titles, and navigation labels.

Recommended: `Configure the export bucket`

Not recommended: `Configure The Export Bucket`
