# Wintermolt

Wintermolt's full-screen TUI, verified end to end on 2026-11-20 with the wintermolt 0.7.0 release binary (built from upstream lupin4/wintermolt revision 8b1a8a2) on macOS through tmux, on an OpenAI-compatible cloud provider.
Verified as a CREWMATE and SCOUT adapter on tmux only; `../../../../../bin/fm-spawn.sh` refuses a secondmate launch and any non-tmux backend because the rendered busy signature lives in the full-screen footer only a pane capture reads.
`../../../../../docs/verification/wintermolt.md` owns how every fact below was established and what is still unproven.

## Operating facts

| Fact | Value |
|---|---|
| Binary | Absolute `wintermolt` from `PATH`, refused if absent. A Zig-compiled single binary whose foreground process name is exactly `wintermolt`. |
| Launch | `wintermolt` bare in the pane: the full-screen interactive view is the supervised surface, with no `--plain` and no `-e`. There is no initial-prompt argument, so the launch follows kimi's and rovo's shape - bare launch, TUI readiness gate, then a typed absolute brief pointer, then a delivery-confirmation gate that requires the busy verdict below. The ready signal is the footer's keybind segment (`Esc quit`), which survives the status-cell truncation a narrow pane applies; the TUI swallows keys typed at its first footer frame (verified live), so the delivery gate retypes the pointer only while nothing is echoed and the composer provably holds nothing, never an echoed one, and reports success only on the busy verdict. |
| Backend and provider | Wintermolt's own documented environment, inherited from the worker environment: `WINTERMOLT_BACKEND` names the backend every mode starts on (ollama default, claude, openai, deepseek, qwen, gemini, kernel, forai), and the chosen backend's own URL/key variables configure it - the OpenAI-compatible surface is `WINTERMOLT_BACKEND=openai` with `WINTERMOLT_OPENAI_URL` (a full chat-completions URL) plus that backend's key variable (verified live against an OpenAI-compatible gateway). Firstmate pins no backend and reads none; `references/common/model-and-effort.md` discovery runs against wintermolt's docs and the live pane, never a catalog firstmate does not own. |
| Model | `WINTERMOLT_MODEL` on the launch env prefix, a bare id for the selected backend, never provider-prefixed; `bin/fm-spawn.sh` refuses a `provider/id` value because wintermolt has no provider namespace and would send it verbatim. The id is not translated for the chosen backend, so discovery is the operator's backend and its own model surface. |
| Effort | None at all. Wintermolt exposes no reasoning or effort setting - only a model id - so a requested effort is recorded and omitted, never invented as a flag or silently mapped to `max`. |
| Busy state | No hook, plugin, or busy-state writer exists, so the rendered-tail fallback in `../../../../../bin/fm-busy-lib.sh` is the only source: the TUI pins one footer row whose keybind segment reads `Esc stop` while a turn runs and `Esc quit` while idle, and whose status cell ends the row with a braille spinner plus `working` while busy and `● ready` while idle (both cells survive the truncation a narrow pane applies to the trailing status). The match is anchored to the pane's last non-empty row so ordinary conversation output containing the word cannot misclassify; absence of the footer is `unknown`, never idle, and a dead pane never reads busy. The launch seeds no busy record (nothing could ever clear it). |
| Composer | A rounded bordered box (`╭`-`│`-`╰`), the shared bordered shape, holding the anchored `Type a message, or /help` placeholder when idle and `working… (Esc stops, Ctrl+C quits)` while a turn runs; the idle row is in the fleet-wide idle-placeholder set in `../../../../../bin/fm-composer-lib.sh`. The busy row reads `pending`, so the doorbell defers on busy rather than typing into a working turn. |
| Turn end | No turn-end hook or notification exists; the worker reports through its status line like every hookless adapter, and supervision reads liveness through the busy fallback above. |
| Interrupt | Single `Escape` stops the running turn and returns the TUI to the ready footer, verified live. The same key QUITS an idle wintermolt outright, draft included, so `../../../../../bin/fm-control.sh` refuses the interrupt verb without a positively proven running turn (the same busy fallback) and never presses blind; after a delivered press it waits - bounded by the control settle window - for the rendered busy verdict to clear, so a following exit never reads the working row that lingers for a redraw moment. |
| Exit | `/quit` typed into a proven-empty composer; the process prints `Goodbye.` and exits to the pane shell. `Ctrl+D` EOF and an idle `Escape` also exit, so no control verb ever sends those. |
| Identity | None. A live bash tool subprocess carried only backend-config variables (`WINTERMOLT_BACKEND`, `WINTERMOLT_MODEL`, provider URL/key names), never an identity marker; `bash` tool children are direct children of the `wintermolt` process, so detection is anchored ancestry alone (`comm wintermolt`), like kimi, muse, agy, devin, kiro, and cortex. |
| Autonomy | No tool-approval dialog exists: the `bash` tool runs commands without asking by default. There is also NO per-tool permission boundary - a refused-command pattern list is a substring check, not a sandbox, and `WINTERMOLT_SANDBOX=docker` is the only isolation and is off by default. That absence is a supervision fact: a wintermolt crewmate runs every tool it is offered on the operator's real account and filesystem, so briefs carry the confinement. |
| Resume | No verified resume form. `/session` exists in the TUI but no automated resume is verified, so the control plane's deterministic `relaunch` re-reads the durable brief, matching the record-and-relaunch posture of every adapter without a verified resume contract. |
| Skills | `~/.wintermolt/skills/` and a `skills` tool exist; no slash-skill form is verified, so use natural language pointing at an installed skill's `SKILL.md`. |

## The fallback hazard and the no-fallback pin

A failed request is retried on local Ollama and then on the OpenAI backend, and only `[fallback]` lines on stderr name the substitution, so a dead model id can be silently answered by a model nobody selected while the pane looks healthy (verified live: a wrong id produced `[fallback] Trying Ollama (qwen3:8b)...` and a full Ollama setup hint).
The launch template therefore pins `WINTERMOLT_NO_FALLBACK=1` unconditionally - never inherited, never overridable by the worker environment - so the chosen backend answers or the turn fails: with the pin, the same wrong id produced `[fallback] off (WINTERMOLT_NO_FALLBACK=1): OpenAI failed (HttpError)`, the reply errored visibly, and `-e` mode exits 1.
An unusable backend is refused earlier still: a backend name that cannot be built, or a cloud backend without its key, prints its reason and exits 1 before the first request, so the pane dies at launch and the readiness gate fails loudly instead of standing up a misconfigured worker.
A provider error inside a `200` stream is treated as a failed request, so a quota or rate-limit refusal falls under the same pin.

## Limits

Only the full-screen TUI on tmux was verified; `--plain`, `-e`, `--web`, `--chat`, `--gateway`, and `--mcp-server` are other surfaces firstmate never drives.
`config/crew-exclude-tools` is not mapped to wintermolt's `WINTERMOLT_TOOL_BLOCKLIST`; a home that lists exclusions refuses a wintermolt spawn rather than running with the tools available, and mapping the list is follow-up work.
The operator's `~/.wintermolt/` startup environment file is loaded on every startup, and shell variables take precedence over it, so the launch-pinned variables above always win.
No primary Stop guard, pre-tool protection, secondmate hook, Herdr lifecycle, or Orca/other-backend surface was verified.
The installed 0.7.0 binary carries a local `forai` HTTP bearer patch (kept in the operator's own packaging); firstmate's adapter deliberately uses only the stock upstream `openai` backend surface, which exists in both the installed binary and current upstream main, so the adapter does not depend on the patch.
