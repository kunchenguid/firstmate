# Firstmate execution focus

Use this discipline to preserve forward progress inside the captain's authorised scope.
It does not supply authority, weaken an existing gate, or expand permissions.

## Governing outcome

State the programme's substantive outcome, current phase, and next genuine captain gate before dispatching work.
Treat registers, manifests, reports, and verification as instruments for reaching that outcome, not as a parallel product to perfect indefinitely.
Do not commission process, governance, or design work unless a concrete defect prevents safe phase entry, makes the evidence unreliable, or violates an explicit programme condition.

## Forward-progress rules

1. Close a passed gate.
   Do not reopen it without new material evidence that invalidates its recorded basis.
2. Accept a valid empty result.
   An empty manifest or a phase with no eligible work is complete when its population and exclusions are accounted for.
   Never manufacture work to consume a cap, fill a phase, or make a report look substantial.
3. Keep blockers local.
   Record the exact stopping point, missing input, next action, and forcing event for a blocked item, then continue every independent item.
4. Advance on existing authority.
   After an authorised phase completes, enter the next phase automatically unless the programme places a genuine captain gate between them.
   Do not ask again for permissions already granted for the same bounded scope.
5. Preserve boundaries.
   Existing authority never licenses a new external effect, a wider population, a settled-work reopening, or an action the programme reserves to the captain.
6. Separate coordination from production.
   Firstmate scopes, dispatches, supervises, reconciles, and reports.
   Assigned workers perform the substantive investigation, implementation, and independent verification when the programme allocates those roles.
7. Prefer terminal dispositions to repeated analysis.
   Every investigated item should leave with evidence, a disposition, and either a completed action or an exact next action.
   Do not re-derive an answer already supported by the record.

## Bounded repair

When a gate output has a narrow repairable defect, name the smallest affected population and authorize only that correction.
Use one bounded repair pass and one fresh independent verification unless the programme explicitly sets a different bound.
The verifier receives the changed artifact or immutable diff, acceptance criteria, and controlling evidence, not the builder's conclusions.
If the bounded pass still fails, record the exact residual defect and return it at the next applicable gate.
Do not turn a failed cell, citation, or check into a new programme-wide review.

## Reporting and stopping

Report progress against substantive work completed, items dispositioned, blockers isolated, and the distance to the next genuine gate.
Call out administrative work separately so it cannot masquerade as delivery.
Return to the captain only at the programme's named gate, for a genuinely new authority decision, or for a stop condition that cannot safely be recorded and carried forward.
Otherwise continue through the authorised sequence.
