# Cortex Code worker verification

Audience: maintainer verification.

Verified 2026-10-12 on Linux x86_64 with Cortex Code `1.1.104` (build `1.1.104+041358.66de1c44636f`) and the live guard re-run on `1.2.14` the same day.
The [adapter reference](../../.agents/skills/harness-adapters/references/harness/cortex.md) owns operating facts; executable owners carry launch and state mechanics.
This verification covers crewmates and scouts, with tmux as the exercised runtime backend and a named Herdr 0.8.2 lab session for the pane-identity and lifecycle checks below.
Primary, secondmate, ACP, Cortex's own worktree and teams modes, and quota-provider integration are outside this guarantee.


The credentialed guard uses the caller's own Cortex connection, a private tmux socket, and the actual command generated by `fm-spawn.sh`.
It spends a handful of small prompts of the caller's Snowflake credits, asks for no SQL, and never names a database object.
Worktree allocation and initial endpoint delivery use the portable fixture; steering and lifecycle control then use the real backend and vendor process.
It fails if the launch adds a project to Cortex's global trust record.
It skips when signed out; the shared live gate owns absent-tool and opt-in behavior.
Failures name the installed Cortex version.

## Observed vendor surfaces

Version output:

```text
Cortex Code v1.1.104
```

`--dangerously-allow-all-tool-calls` (alias `--bypass`) processed a positional initial prompt after `--` and ran shell tools without a permission prompt.
The same flag skipped the `Do you trust this project?` dialog and wrote nothing to `~/.snowflake/cortex/cortex.json`.
Without it, the dialog offers `1. Yes, proceed` and `2. No, exit`, and answering no exits the process.
The footer under the composer then reads `>> bypass safeguards | teams: off | plan: off | guard: on`.
`guard` is the SQL read-only setting (`--sql-read-only`, `CORTEX_CLIENT_READ_ONLY=1`), which the launch does not pass.

Hook sources the build reads are the user hook file `~/.snowflake/cortex/hooks.json`, `settings.json` under `~/.claude/` and `~/.cortex/`, the project's `.claude/` and `.cortex/` `settings.json` and `settings.local.json`, and plugin directories passed with `--plugin-dir`.
A plugin directory is loaded only with a `.cortex-plugin/plugin.json` manifest beside `hooks/hooks.json`.
Project hooks load without a trust grant.
`--config <file>` replaces the user `settings.json`, whose `hooks` are then not read, and a missing theme or connection reopens the onboarding dialogs.
`--setting-sources` does not gate hooks.
`SNOWFLAKE_HOME` relocates `~/.snowflake`, which the live guard does not use.

The plugin's native hook log recorded these payload fields, each with `session_id`, `transcript_path`, `cwd`, and `hook_event_name`:

```text
SessionStart source=startup
UserPromptSubmit prompt=<text>
Stop stop_hook_active=false
SessionEnd reason=prompt_input_exit
```

`Stop` fires on normal completion and on an Escape interrupt.
The generated hooks produced `idle cortex-hook` semantic state and the turn-ended notification after each `Stop`.
`--session-id` is ignored for an interactive session, and the session id in every payload equals the id the exit summary prints.

A running turn renders a spinner row such as `⠙ Snowdiving...  (esc to interrupt)`, the composer placeholder `Type to queue message...`, and a footer starting `view: compact • Type to queue next message • esc to i`.
The idle composer is a rounded box whose top rule carries the session title, with the placeholder `Type your message...` and the footer `view: compact • ? for help •`.
Text typed while a turn runs is listed under `Queued (↑ to edit, Enter to send next):`, and an Escape interrupt lets the queued message start as the next turn.
Dim follow-up suggestions under the box (`push it`) are ghost text.
Ctrl+U clears the composer.
Cortex parks the terminal cursor in column 0 of the blank row under its footer, so the cursor-anchored tmux read cannot find the composer; the classifier reads such a pane cursorlessly for a foreground process named exactly `cortex`.
The titled rounded top rule is accepted as a composer only for a pane whose foreground process is proven `cortex` (tmux exact process name, Herdr native agent probe); the same box on any other pane stays ambiguous.
`NO_COLOR=1` still classified an empty composer.

One Escape on a running turn cancels it and prints an `Interrupted` line telling Cortex Code what to do next; `Stop` fires and the process stays.
Escape on an idle composer, single or doubled, does nothing.
Ctrl+C also cancels a running turn and does nothing visible when idle; the adapter does not use it.
`/quit` followed by Enter, with the shared slash-popup settle, returns to the shell and prints `cortex --resume <session-id>` and `cortex --resume last`.
`cortex --resume <session-id>` restored the conversation and fired `SessionStart source=resume`.

`--model <id>` accepts the ids an unavailable-model error lists on this account (`claude-sonnet-5-5`, `claude-haiku-5-5`, `claude-opus-4-6`, `auto`, `auto-fast`, among others); an unknown id is not refused at launch and errors after the first prompt.
`--effort` accepts `minimal`, `low`, `medium`, `high`, and `max`.

## Commit attribution

The model writes `Generated with [Snowflake CoCo](https://docs.snowflake.com/en/user-guide/cortex-code/cortex-code)` and a `Co-authored-by: Snowflake CoCo <noreply@snowflake.com>` trailer into commit messages it composes; the built-in `/commit` command writes `Generated with [Cortex Code](https://docs.snowflake.com/user-guide/snowflake-cortex/cortex-agents)`.
No client setting turns either off, so the spawn-owned commit-msg strip is the only control, and the live guard's worker commit carried neither.
The strip does not edit text the model places in a PR body.

## Herdr lab session

A named Herdr 0.8.2 lab session, with the captain's real `~/.claude/settings.json` hooks and the captain's own Cortex Herdr hook present, showed:

```text
unguarded launch (CLAUDECODE=1 inherited):
  agent_session {agent claude, source herdr:claude}   claim made by the Claude integration hook
  after /quit: agent_not_found; claim persists
  later report-agent --source firstmate:cortex: ignored, agent get still agent_not_found

guarded launch (env -u CLAUDECODE):
  no agent_session claim
  after /quit: agent_not_found
  later report-agent --source firstmate:cortex: accepted, agent get reports working
```

Herdr 0.8.2 carries no Cortex entry in its agent-detection manifest, so a Cortex pane with no reporting hook answers `agent_not_found` for `agent get` and `fm_backend_agent_state` classifies it `dead` while the process is alive.
`fm_task_inbox_ring` returns 3 and skips the doorbell for a `dead` endpoint.
With the per-task plugin hooks on the same lab pane, the logged calls were:

```text
pane report-agent <pane> --source firstmate:cortex --agent cortex --state idle
pane report-agent <pane> --source firstmate:cortex --agent cortex --state working
pane report-agent <pane> --source firstmate:cortex --agent cortex --state idle
pane release-agent <pane> --source firstmate:cortex --agent cortex
```

and `fm_backend_agent_state herdr` read `alive`, `fm_backend_composer_state herdr` read `empty`, and the busy record read `idle cortex-hook`.
Through the real control plane on a lab pane, an idle `fm-control interrupt` answered `interrupt-delivered ... verified=agent-alive cancel=unconfirmed`, `exit` stopped the worker and read `dead` afterward, and `relaunch --note` restarted it so the new process read the launch brief and the steering inbox.
Unlike Devin, `exit` does not refuse on Herdr, because the cursorless composer classifier proves the Cortex composer.

## Coverage and limits

The portable regression drives ancestry evidence and its rejection of unrelated names, worker-only resolution, the captured idle, busy, and draft composer shapes, independent delivery signals, the plugin lifecycle with stale-generation rejection, the Herdr reporting clause both inside and outside Herdr, and the scout launch's autonomy, plugin, typed brief, model, and effort handling with `xhigh` omitted.
The live guard checks launch, brief execution, model flag, trust skip, tool ancestry, native `Stop`, commit attribution, doorbell acknowledgement, idle and busy interruption, process liveness, exit, and native resume.

Not verified and therefore unsupported:

- `cortex --continue` and `cortex resume --last`, which appear in `--help`; only a session id read from the exit summary or a hook payload was exercised.
- End-to-end skill invocation through `fm-send`; the slash popup lists user skills, but none was sent as a command.
- Whether `Stop` fires for a turn that ends in a model error; such a worker on a rendered error is a stale-worker case.
- Cortex's onboarding dialogs, which a fresh home with no theme or connection opens; the launch has no backstop signature for them.
- Whether a later Herdr release recognizes Cortex natively; the self-registration hooks then report from a second source.
- Zellij, Orca, cmux, Paseo, rex, and T3 Code, which were not exercised; `fm-spawn.sh` refuses a cortex launch on them because only tmux and Herdr supply the Cortex pane identity that proves its titled composer empty.
- Any primary or secondmate supervision, so the adapter refuses both.

The launch does not pass `--sql-read-only`, so SQL write policy remains the operator's own Cortex configuration, and the account's connection is used as configured.
Cortex imports Claude-compatible hook files with no switch to disable the import, so a project with Claude hooks runs them in a Cortex worker.
